# 380 HDMI 1대 10분 연속·분리 복귀 수락 — 2026-11-11

**실보드에서 HDMI 모니터 1대의 통합 화면을 600초 연속으로 확인했고, 케이블 분리·복귀도 확인해 380을 완료했다.** 복귀 뒤 모니터 화면의 좌우 절반이 바뀌어 보이는 경우가 있었다. 모니터 전원을 껐다 켜면 복원됐으므로 모니터 쪽 현상으로 판단했다. 이 문서는 시험 기록이며 코드 변경은 없다.

## 기준·환경

- 보드: Raspberry Pi 4, Xen dom0, 이미지 Xenova 6.0.4, 커널 6.18.33.

- 출력: `HDMI-A-1` 모니터 1대, 1920×1080@60, KMS(`vc4-kms-v3d-pi4`).
- 화면 경로(Plan A):
  - Interaction VM의 guest display app이 웹 앱을 제공한다.
  - dom0 Chromium 키오스크가 `/display/combined`를 그려 HDMI로 출력한다.
  - 11/10에는 Debian VM(192.168.77.6, 템플릿 1.0.6)을 썼다.
  - 11/11에는 새 Interaction VM 1.0.7(192.168.77.5)로 다시 확인했다.
- 키오스크 코드는 현재 platform과 같다.
  - `xenova_display/kiosk.py`: sha256 `84d8834ed7b2…`
  - `xenova_display/outputs.py`: sha256 `de14cdaa4224…`
- 보드 이미지의 제품 설치는 바꾸지 않았다.
  - 대신 같은 코드로 띄운 임시 KMS 세션(transient unit `xenova-display-hdmi-1110`)으로 시험했다.
  - 제품 unit `xenova-display-hdmi`의 재부팅 후 HDMI 기본 확인은 이 문서 범위가 아니다(390/351).

## 3. 복귀 뒤 화면 좌우가 바뀌는 현상

복귀 뒤 모니터에 화면 좌우 절반이 서로 바뀐 채 표시되는 경우가 있었다.

- 이때도 X/KMS 출력은 정상이었다: 1920×1080@60, 위치 +0+0, 분리 전과 같은 EDID.
- 다음 방법은 일관되게 고치지 못했다.
  - 모드 재적용(`--off` 뒤 `--mode`)
  - 주사율 변경(59.94↔60Hz)
  - 해상도 변경
  - Chromium만 재시작
  - X 세션 전체 재시작: 11/10에 한 번은 고쳐졌지만 11/11 재시험에서는 고쳐지지 않았다.
- 보드를 건드리지 않고 **모니터 전원만 껐다 켜면 정상 화면으로 복원**됐다(11/11, 새 Interaction VM 1.0.7 화면).
- 판단: 모니터가 새 신호를 잡을 때 화면 위치를 잘못 잡는 모니터 쪽 현상이다. 그래서 출력 재설정이나 세션 재시작 같은 코드 변경은 채택하지 않았다.

### 운영 안내

HDMI를 다시 꽂은 뒤 화면이 좌우로 밀려 보이면 모니터 전원을 껐다 켠다. 보드나 표시 서비스는 다시 시작하지 않아도 된다.
